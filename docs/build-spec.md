# PASS 1 — DRAFT (ARCHITECT-A) — Diagnosis 2026-08-29

## Project Summary (as audited)
Spotify-FY is a full-stack Spotify clone: Flutter (Riverpod + audioplayers + youtube_explode_dart + cached_network_image) + Node/Express backend (yt-dlp via `yt-dlp-exec`, Mongoose, JWT auth, optional Redis/Cloudinary/Firebase). Music is scraped from YouTube without API key. Current state: **functional locally but fragile in prod** — Android build fails on Kotlin/Gradle, playback takes 6-20s and fails on Render datacenter IPs, `Song` model validation breaks caching, volunteer Invidious fallbacks are unreliable, and `docs/build-spec.md` was drifted to a completely unrelated Graceselle portfolio spec.

ARCHITECT-A diagnosed 4 buckets:
- **P0 Build/Spec drift:** Graceselle spec in `docs/build-spec.md` (100% wrong), `opencode.json` model `gpt-5.6-sol` invalid, `docs/` ignored in `.gitignore` so spec not versioned, `google-services.json` committed.
- **P0 Playback:** yt-dlp bot-checks on Render, `TRENDING_PLAYLIST_URL` dead (`The playlist does not exist`), Invidious hosts (`inv.tux.pizza` etc) via `api.allorigins.win` add 15-24s sequential latency, `googlevideo` URLs expire ~6h but cached 12h, Windows-only `backend/bin/yt-dlp.exe` will fail on Linux deploy.
- **P1 Backend:** `Song.channelId: required: true` but `formatFlatEntry()` can be `''` → `Song validation failed: channelId is required` even when DB connected (logs confirm), Redis/Cloudinary/Firebase silently disabled, CORS single-origin breaks GitHub Pages + localhost.
- **P1 Frontend:** 18 `flutter analyze` infos (`withOpacity` → `withValues`, `activeColor` → `activeThumbColor`, `SizedBox` lint), complex 3-tier fallback in `player_provider.dart`/`web_audio_service.dart`/`direct_audio_service.dart` with mismatched timeouts (20s/60s/90s), `api_base_url_io.dart` LAN IP foot-gun, mini-player not `SafeArea` aware.

# PASS 2 — FINALIZED (ARCHITECT-B)

## Critique of the Draft

Draft diagnosis is accurate but underspecified as a build prompt. Gaps fixed here:

1.  **Spec drift is a P0 blocker, not polish.** The Graceselle spec must be voided. `docs/` being gitignored means BUILDER's work is invisible to git — fix `.gitignore` first or every milestone `git-ops` push is a no-op. `opencode.json` model invalid will break subagents.
2.  **"Fix build" too vague.** Must name exact failures: `gradle_out.txt` `Could not download arm64_v8a_debug... Read timed out` is not just network — it's Kotlin `2.2.20` vs embedded `2.2.0` + `android.builtInKotlin=false` deprecated. Fix is: remove `android.builtInKotlin`/`newDsl` flags per `kotl.in/gradle/agp-built-in-kotlin`, align AGP 8.x/Kotlin 2.2.0, keep `gradle-wrapper.properties` 8.7+.
3.  **Playback plan was hand-wavy.** Need explicit strategy order (android → ios → mweb → default → tv_embedded) + deadlines (15s per strategy, 60s hard), TTL (5h not 12h), and race semantics. Current uncommitted `Promise.any([Invidious, yt-dlp])` in `audioService.js` is correct direction but needs expiry-aware `isAudioCacheValid()` and must not cache Invidious proxy URLs that 410 quickly.
4.  **Invidious fallibility understated.** `inv.tux.pizza`/`yewtu.be`/`vid.puffyan.us` are best-effort. Spec must state: Invidious is **fallback only, never primary**, sequential with 5s abort per host, total budget 15s, and must be disabled if 2 hosts fail in a row (circuit breaker). Primary is `yt-dlp` with `android` client; secondary is server `/audio` proxy (which itself uses `yt-dlp`).
5.  **Song model fix under-designed.** Making `channelId` optional is safer than defaulting `''` — empty string still fails `required`. Change to `required: false, default: 'unknown'` + migration for existing docs. Also `viewCount`/`duration` need `default:0` handling for shorts.
6.  **CORS & binary not actionable.** Must state: production `cors.origin` = Array of `FRONTEND_URL` split on `,` (GitHub Pages URL + localhost + `*` for dev), and `backend/bin/yt-dlp` must ship Linux binary (`yt-dlp_linux`) with `YT_DLP_PATH` env override; keep `yt-dlp.exe` for local win dev.
7.  **Frontend Scope creep risk.** Proposing "fix all 18 lints + player + search + API URL" in one milestone guarantees a broken push. Split: M1 hygiene (lints + build), M4 UX (player/search) — lints are mechanical and must land first.
8.  **Missing verifiability.** No way to prove playback fixed without a repro script. Add `GET /api/debug/ytdlp?videoId=kJQP7kiw5Fk` probe already exists — require it to pass for 3 videoIds in CI.

Additional fixes not in draft:
- `google-services.json` must be removed from git history or at least gitignored going forward (`android/app/google-services.json`); add replacement docs in `.env.example`.
- `render.yaml` must pin `YT_DLP_PATH=./bin/yt-dlp_linux` and document `YOUTUBE_COOKIES` (Netscape format) for Render bot-bypass — already partially implemented via `YOUTUBE_COOKIES` env in `youtubeService.js`.
- `audioplayers` 6.0.0 `UrlSource` needs `ReleaseMode.stop` already set — keep, but verify `setVolume` after `resume` not before.
- Secrets: `FRONTEND_URL`, `MONGODB_URI`, `JWT_*` must never be logged; `cacheGet/Set` must handle Redis `null` without throwing.

## Resolved Open Questions (defaults, decided)

1.  **yt-dlp vs Official API:** Keep **yt-dlp** (no quota, matches repo). Official API would require key rotation and still not give audio URLs. Decision: stay on yt-dlp + direct `youtube_explode_dart` on mobile.
2.  **Invidious:** Keep as **fallback only, 5s/host, 15s total, circuit breaker** — not primary. If Render fixes yt-dlp via cookies, Invidious rarely fires. Do not add more hosts beyond 4.
3.  **Platforms:** **Android + Web MVP**, iOS best-effort (no Mac CI to verify). Web must use server `/audio` proxy (CORS), mobile can use direct `youtube_explode`.
4.  **DB/Redis:** Keep **Atlas required, Redis optional** with **in-memory Map fallback** (already in `config/redis.js` pattern). Don't require Redis for MVP.
5.  **CORS:** Production: `origin: FRONTEND_URL.split(',')` trimmed; dev/test: `true`. Never `*` with `credentials:true` in prod.
6.  **Secrets:** `google-services.json` → **gitignore** `android/app/google-services.json` from now; keep existing commit but document "rotate if public repo". New devs create local file, CI uses secret var.
7.  **Cache TTL:** Cut to **5 hours** (not 12) — below `googlevideo` 6h expiry. Change `AUDIO_CACHE_TTL_HOURS default 5`, `isAudioCacheValid()` uses same.
8.  **Graceselle drift:** **Void** — `image.png` / portfolio assets never existed in this repo; no deletion needed. `docs/build-spec.md` now correctly describes Spotify-FY.

### M2 — Backend Data & Cache Correctness
**Goal:** DB writes never block playback, cache is truthful.
- `Song` schema: `channelId: {required:false, default:'unknown'}`, `duration: required false default 0`, `thumbnailUrl` fallback to `https://i.ytimg.com/vi/${videoId}/hqdefault.jpg`. Add migration: `db.songs.updateMany({channelId:''}, {$set:{channelId:'unknown'}})`.
- `config/index.js`: `AUDIO_CACHE_TTL_HOURS` default `5`; `isAudioCacheValid()` uses `config.audio.cacheTtlHours`.
- `youtubeService.js`: keep fallback but ensure `formatFlatEntry` never returns `channelId: ''` → `'unknown'`; handle `entry.duration` string vs int.
- Trending: keep parallel search fast-path (`top hits 2025` etc) as primary; demote `TRENDING_PLAYLIST_URL` to optional with 25s timeout; document that playlist may be dead.
- CORS: `app.js` → `origin: config.frontend.url.split(',').map(s=>s.trim()).filter(Boolean)` in production; update `.env.example` `FRONTEND_URL=https://merjohnpagente.github.io/spotify,http://localhost:5173`.
- Binary: add `backend/bin/yt-dlp_linux` (or document curl install in `render.yaml` buildCommand), set `YT_DLP_PATH=./bin/yt-dlp_linux` in `render.yaml` env.
**Commit:** `fix: song model, cache TTL 5h, CORS, trending + binary`

### M3 — Playback Reliability (core, PureTuber-fast)
**Goal:** Tap-to-play p50 <3s on warm cache, <8s cold, no 60s hang.
- Finalize `audioService.js` race already in worktree: `Promise.any([fetchViaInvidious(5s/host), extractWithFallbacks(15s/strategy, 60s deadline)])`. Invidious sequential 4 hosts ×5s=20s max but race means yt-dlp usually wins in 6-10s (android first). Keep but add: don't cache Invidious URLs if `url.includes('googlevideo')===false` (proxy), and mark `preferredStrategy='invidious'` only if googlevideo.
- `extractWithFallbacks`: order `android, ios, mweb, default, tv_embedded, web_embedded`; `preferredStrategy` memory; 60s hard deadline; `runWithRunner` SIGKILL already correct.
- `extractAudioUrl`: check Redis `audio:videoId` → Mongo `isAudioCacheValid()` 5h → race → `Song.findOneAndUpdate` best-effort → `cacheSet` 5h.
- `songController.audioProxy`: pipe with `Range` + `CORS` headers, handle 403 expiry → clear cache and re-extract once.
- Frontend `player_provider.dart`: keep `DirectAudioService` (mobile) 20s timeout → fallback to `MusicService.getStreamUrl` → fallback to `getAudioProxyUrl`. Web: `WebAudioService` (Invidious via `allorigins`) 8s → proxy. Ensure `duration` init from `song.duration` before load, remove duplicate `LinearProgress`.
- Add `GET /api/debug/ytdlp?videoId=kJQP7kiw5Fk&strategy=android` must pass for 3 ids (adele hello `hLQl3WQQoQ0`, `kJQP7kiw5Fk`, one from trending) in test.
**Commit:** `fix: playback race + 5h TTL + proxy range + strategy order`
